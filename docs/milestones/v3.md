# V3 Milestone — Immersive Game Translation

## Status

Planned — design draft under review (`docs/features/v3-game-translation.md`).

## Goal

Add low-latency translation for dynamic game content, drawn to fit the game's
interface, while reusing the common translation architecture.

## Spikes first

The design rests on three platform facts nobody has measured. Each is a small
throwaway experiment on the phone; if one fails, the feature definition changes
before any of the work below starts.

- [ ] **Window screenshots.** `takeScreenshotOfWindow` on a running game: is
  Babel's own overlay absent from the picture, how often can it be taken, and
  does the game block it?
- [ ] **Horizontal OCR on game text.** The on-device general engine over
  `material-sample/game/`: accuracy and time per screenshot, and whether the
  "do not translate" rules separate dialogue and buttons from numbers and logos.
- [ ] **Tap pass-through.** A touchable translation that hands a short tap on to
  the game with `dispatchGesture` and shows the original on a long press: how
  long the hand-off takes, and whether games accept the injected tap.

## Planned Work

- [ ] Game mode switch, and recognising games (system category, plus manual add)
- [ ] Window-only frame source (API 34)
- [ ] Region change detection and text stability (typewriter lines)
- [ ] Horizontal OCR path normalised to `TextElement`
- [ ] "Do not translate" rules: numbers, artwork backdrop, unstable readings, short Latin labels
- [ ] Erase-and-redraw rendering that fits the original's panel, colour and alignment
- [ ] Long press for the original, short tap passed through
- [ ] Interface-text cache and dialogue context
- [ ] Obsolete-work cancellation
- [ ] Throttling when still; battery and thermal review
- [ ] Remembering a game's language when it matches the target
- [ ] V3 privacy review for dynamic capture
- [ ] Optional: per-game profile (terms, hand-marked regions)
- [ ] V3 acceptance testing against the feature's criteria
