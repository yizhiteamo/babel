# V3 Milestone — Immersive Game Translation

## Status

Active — the three spikes hold; the skeleton runs end to end on a real game.

## Goal

Add low-latency translation for dynamic game content, drawn to fit the game's
interface, while reusing the common translation architecture.

## Spikes first

The design rests on three platform facts nobody has measured. Each is a small
throwaway experiment on the phone; if one fails, the feature definition changes
before any of the work below starts.

- [x] **Window screenshots.** `takeScreenshotOfWindow` on a running game: is
  Babel's own overlay absent from the picture, how often can it be taken, and
  does the game block it? — **holds** (results below)
- [x] **Horizontal OCR on game text.** The on-device general engine over
  `material-sample/game/`: accuracy and time per screenshot, and whether the
  "do not translate" rules separate dialogue and buttons from numbers and logos.
  — **holds**, with three faults to design around (results below)
- [x] **Tap pass-through.** A touchable translation that hands a short tap on to
  the game with `dispatchGesture` and shows the original on a long press: how
  long the hand-off takes, and whether games accept the injected tap. — **holds**,
  with one ordering rule that must be kept (results below)

## Spike 1: window screenshots (2026-10-07, phone, Android 15)

Blue Archive (Unity, `com.YostarJP.BlueArchive`) in a story scene, landscape,
with manga mode on so Babel's translations were drawn over the dialogue. A
temporary probe in the accessibility service took one whole-display screenshot
and then window screenshots of the game's application window.

| Question | Answer |
|---|---|
| Is Babel's overlay in the picture? | **No.** The display screenshot shows the translated dialogue and buttons; the window screenshot of the same moment shows the original Japanese, untouched. |
| Resolution | Full: 3200×1440, same as the display |
| Time per screenshot | **60–110 ms** |
| How often | **About every 333 ms**, the same limit as whole-display screenshots: requested ~205 ms apart, every other one failed with `ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT`; ~300 ms or more apart, all succeeded |
| Does the game block it? | No |
| Window list | The game is one `TYPE_APPLICATION` window (title ブルアカ); Babel's overlays are separate windows above it, so picking the game's window is unambiguous |

Consequences for the design:

- The core premise holds: once a translation covers the original, the next
  line is still visible to Babel, with **no clear-and-recapture** — the cost
  manga mode pays on every page turn is gone for game mode.
- Frames arrive at ~3 per second, so a finished line is seen within ~333 ms;
  the stability check ("two frames the same") costs at most ~666 ms. That is
  the floor of the latency budget, before OCR and translation.
- **Recognising a game needs package visibility.** Asking the package manager
  for the game's category failed (Android 11+ hides other packages). The
  manifest needs a `<queries>` entry before "only in games" can rely on
  `ApplicationInfo.category`.
- In passing, manga mode run on this game showed why games need their own path:
  both `AUTO` and `MENU` came back as 菜单, and a 正在加载…… appeared where the
  ▼ continue mark is. The manga recogniser and detector are not for game UI.

## Spike 2: horizontal OCR on game screenshots (2026-10-07, phone)

`GameOcrMeasurementTest`: ML Kit's Japanese model over the five screenshots in
`material-sample/game/`, each scaled to the phone's 3200×1440, three timed runs
after a warm-up. The backdrop signals were then computed off the device from
the same images and the returned boxes.

**Time for a whole frame:** 150–210 ms for a story scene (4 lines), 300–430 ms
for the lobby (33 lines). Recognition time follows the amount of text, so
reading only the region that changed is also the way to keep it short.

**What it read:**

| Screen | Result |
|---|---|
| Dialogue (ba-004) | The line exactly right. Speaker and affiliation came back as **one line** (ツムギワイルドハント芸術学院) |
| Choices (ba-003) | Both exactly right, except `……` read as `。`/`…` |
| Pop-up body (ba-002) | Line 1 exact; line 2 dropped one character (糸巻き → 巻き) |
| Character bubble (ba-001) | Exact, `……` dropped |
| Small icon labels (ba-001) | Most right; four misread or merged (モモトーク → 藍トーク, two labels joined) |
| Yellow outlined lettering (ba-002) | Badly misread (イペントアイテムを種得) |
| Logo (ba-005) | Misread, and boxes 8–29% of the screen high |

**"Do not translate" — the signal works.** For each line, predict the band just
above and below it by interpolating, row by row, between the pixels at its left
and right ends; the mean error says how plain its backdrop is. It is also
exactly the test of whether erase-and-redraw will look clean.

| Text | Interpolation error |
|---|---|
| Choices, pop-up body, pop-up title | 0.2–0.9 |
| Dialogue line, speaker line, bubble | 4–7 |
| Interface labels on plain bars | 1.3–5 |
| Stylised lettering, banner text, labels drawn on icons | 14–68 |
| Logo | 26–59, and over 7% of the screen high |

A threshold near 12, plus line height under ~7% of the screen, plus the number
and short-Latin rules (155/240, 264,410,355, 17:13, Lv. 90, AUTO, MENU, MAX),
put every line in the right group on these five screens: dialogue, choices,
pop-ups and plain labels translated; logos, stylised lettering, art-drawn labels
and numbers left alone. Five screens of one game prove the signal, not the
threshold — it is to be checked on other games.

**Three faults to design around:**

- **Lines of different style merge.** Speaker and affiliation are one "line" to
  the engine. Drawing them back needs splitting on colour and gap, and the
  speaker name is worth knowing separately for dialogue context.
- **Small drops and ellipses.** A missing character or a lost `……` passes
  straight into the translation. Reading the same line on two consecutive
  frames — which the stability check does anyway — gives a second reading to
  compare, at no extra capture cost.
- **Misread labels are on art.** The labels it got wrong are the ones the
  backdrop rule already skips, so the error does not reach the screen.

## Spike 3: tap pass-through and long press for the original (2026-10-07, phone)

A temporary probe in the accessibility service put a touchable stand-in
translation (`TYPE_ACCESSIBILITY_OVERLAY`) over Blue Archive's dialogue box,
and taps were sent with adb. To hand a short tap on, the window makes itself
`FLAG_NOT_TOUCHABLE`, injects a tap at the same point with `dispatchGesture`
(capability `canPerformGestures`, which the service config does not yet
declare), and becomes touchable again 150 ms later.

**The game accepts the injected tap.** Each tap advanced the dialogue by one
line, exactly as tapping the game does.

**The trap, measured:** turning the window untouchable takes about **80 ms** to
reach the input system. Inject sooner and the tap lands on Babel's own window
again, which then hands it on a second time:

| Wait before injecting | Taps handed on, for 3 adb taps |
|---|---|
| 0 / 16 / 32 ms | 6 — each tap caught once by Babel's own window |
| 50 ms | 5 |
| 80 ms | 3 — correct |

**The fix that also removes the latency:** make the window untouchable **at
touch-down**, not at release. The rest of a touch that started on a window
keeps going to that window, so the press and release still reach Babel; only
the injected tap that follows goes through. A human tap lasts long enough for
the change to land:

| Tap held for | Taps handed on (of 3) | Release → game receives the tap |
|---|---|---|
| 80 ms | 3 | 25–30 ms |
| 120 ms | 3 | 18–28 ms |
| adb's ~10–40 ms | too many | — |

So the rule for the real thing: untouchable at touch-down; at release, inject
at once if at least ~80 ms have passed since touch-down, otherwise wait until
they have. A normal tap then costs the player **~20–30 ms**; only the shortest
flick costs up to ~100 ms.

**Long press for the original works.** Held for 2.5 s: after 450 ms the stand-in
became transparent and the game showed through; on release it came back, and no
tap reached the game, so a long press never advances the dialogue.

## Skeleton: end to end on a real game (2026-10-07)

Game mode as a third switch on the home screen; `:platform:game`
(`GameTextSource`) reads the game's window, `GameTextFilter` drops what is not
worth translating, `StableLines` publishes a line when two frames agree, and
the common coordinator and overlay do the rest. Lines are drawn in the existing
box for now — erase-and-redraw and tap pass-through come next.

- **Recognising a game works.** Blue Archive declares `CATEGORY_GAME` (0), read
  through the manifest's `<queries>`. Manual add for games that do not declare
  it is still to do.
- **Translated, end to end**, on four advances of the story: speaker line,
  dialogue lines and the AUTO/MENU buttons (自动, 菜单).

**Latency, from the tap to the translation drawn** (remote chat provider):

| Advance | Tap → line settled | Settled → translated | Total |
|---|---|---|---|
| 1 | 1.76 s | 0.63 s | **2.4 s** |
| 2 | 1.87 / 2.38 s (two lines) | 0.57–1.07 s | **2.9 s** |
| 3 | 2.14 / 2.66 s (two lines) | 0.62–0.92 s | **2.8–3.6 s** |

Where the time goes, and what each fix is worth:

- **A frame every ~470 ms, not 333.** Capture (~80 ms) and recognition
  (160–360 ms) run one after the other, so the loop is slower than the
  platform allows. Taking the next picture while the last is being read brings
  it back to ~333 ms.
- **Settling costs a frame after the line is complete**, by design; at 333 ms a
  frame that is ~0.35 s instead of ~0.5 s. Part of "tap → settled" is the game's
  own typewriter animation, which no reader can shorten.
- **Reading only the region that changed** cuts recognition from 160–360 ms to
  the dialogue box alone.
- **Translation 0.57–1.07 s** is the provider; a cached interface label is 0 ms.

**Faults seen, for the next steps:**

- Speaker and affiliation are still one line (ツムギワイルドハント芸術学院), and
  translate badly as one. Splitting on colour and gap is needed.
- Two lines of one utterance are translated separately; they should be joined
  into one translation unit, as manga mode joins a balloon's lines.
- The existing box is opaque black and does not fit the game's panel — the
  erase-and-redraw step.
- Game mode reads continuously while a game is in front (OCR every frame, about
  half of one core); throttling when nothing changes is still to do.

## Where manga mode and game mode met (2026-10-07)

Three conflicts between V2 and V3, each confirmed on the phone and fixed:

- **Manga mode read games.** With game mode off, the comic recogniser read
  Blue Archive's screen (AUTO and MENU as 菜单, an invented loading line).
  A declared game is now game mode's alone: manga mode skips it whether game
  mode is on or not (`image scan skipped: a game, which is game mode's`).
- **A tap on a game translation was swallowed.** Game lines were drawn in
  manga mode's touchable windows, where a tap toggles the original. Game
  translations now hand a short tap on to the game (`TapForwarder`,
  `dispatchGesture`) and show the original while long-pressed, with the
  window untouchable from touch-down (spike 3's rule). Measured: a tap on the
  dialogue advanced it, a tap on a translated choice chose it, a 1.5 s press
  showed the original and did not advance.
- **The quick-settings tile ignored game mode.** It now pauses and restores
  game mode with the other two.

Seen in passing: the speaker label (通行人A) was not translated — to look at
with the speaker/affiliation split.

## Faster: frames at the platform's pace (2026-10-07, phone)

Two changes, measured on Blue Archive with six story advances each time:

- **The next picture is taken while the last is read** (`GameTextSource.read`
  runs its own loop and prefetches the next window frame).
- **Window frames are paced start to start.** The pacing counted 400 ms from
  when the last picture *arrived*, so a capture's own 60–110 ms was added to
  every frame. Window frames are now asked for 350 ms after the last was asked
  for, which spike 1 showed the platform allows; no capture was refused in 110
  frames.

| | Before | After |
|---|---|---|
| Frame interval, median | 484 ms | **351 ms** |
| Tap → line settled, median | ~2.1 s | **~1.5 s** (1.23–1.75 s; one outlier at 4.4 s across a scene change) |

Part of "tap → settled" is the game's own typewriter animation, which nothing
on Babel's side shortens.

**Reading only the changed band did not pay off in this game.** The frame is
compared on a 64×29 brightness grid, and only the rows that changed are read
again (`ChangedBand`). Blue Archive's characters and backdrop are animated even
while nothing is said, so 88 of 111 frames changed over more than half the
height and were read whole; 17 were unchanged and 6 read as a band. It stays —
it costs a scaled bitmap per frame and helps any game with a still scene — but
the speed above comes from the pacing, not from it.

## Accurate: speakers, affiliations and wrapped lines (2026-10-08)

`GameLayout`, measured on Blue Archive screenshots through the whole path
(`GameTextSourceReplayTest` feeds a still picture to `GameTextSource`;
`GameLayoutDumpTest` prints ML Kit's blocks, lines and elements):

- **Speaker and affiliation split.** ML Kit returns 「ツムギワイルドハント芸術学院」
  as one line and one element, so the cut is found in the pixels: the name is
  white, the affiliation cyan, 34 px apart. A gap is cut when the ink on its two
  sides differs in colour, judged over all the ink on each side — judged on
  neighbouring glyphs alone, thin ones (ト, ッ) split words in two. Each piece is
  read again on its own, and cached. Result: 「ツムギ」 / 「ワイルドハント芸術学院」.
- **Wrapped lines joined.** The two lines of one speech are separate blocks to
  ML Kit and were translated as two sentences. Lines of the same size of type,
  close below and at about the same left edge are one utterance now; a
  speaker's larger name and choices a button apart are not joined. The pop-up's
  two lines and 「う、ウソだろ?」+「こんなすごい演奏を…」 each became one.
- **Speaker labels kept.** 「通行人A」 sits on the art at the box's edge and
  scored 15 on the backdrop test (threshold 12). A label turned down for its
  backdrop alone, within twice the threshold, is kept when a translated line
  starts right below it. Lettering on art with nothing translated below stays
  out (the yellow 「イペントアイテム…」 at 20 still does).

### On the live game (2026-10-08)

Five advances at a time in a convenience-store scene with animated
characters behind the dialogue box. The first runs showed what screenshots
could not:

- **One refused crop dropped the whole frame.** A split piece under 32 px made
  ML Kit throw, and the exception left the frame unread — 43 frames read as
  nothing. Pieces are now padded with the frame around them and refused
  individually.
- **AUTO and MENU were one line on some frames and two on others**, and each
  flip withdrew and redrew their translations. A line is now cut where its
  words stand further apart than the line is tall; a bracket set apart stays
  with its words.
- **A name cut through a line of dialogue** where the art behind changed
  colour. Only one cut, in the line's first 45%.
- **A still line read slightly differently every frame** on moving art, and
  each variant withdrew the translation. Two readings of about the same length
  sharing 85% of their characters are the same line, and a published line keeps
  the reading it was published with.
- **Translations drawn 552 px right and 160 px low.** The game's window bounds
  were taken while it was still animating back to the front and kept for the
  whole read; a change in bounds now ends the read.
- **Scenery text** (price tags 23–38 px) flickered in and out: type under 2.8%
  of the frame height is not read. A published line now survives four missed
  frames instead of two.
- **Speaker rows on art** scored 24–31 (character behind a translucent box) and
  long dialogue lines 11–18: a name row within four times the threshold above
  translated dialogue is kept, and a line over 40% of the frame wide is
  dialogue within twice the threshold.

Result over five advances: withdraw/redraw churn 50 → 14 shows; names and
affiliations translated separately (小优 / 研讨会, 空 / 天使24); wrapped dialogue
translated whole; positions correct. Translations are still the existing
opaque box, at varying sizes — the next step, erase-and-redraw.

### Second pass on the live game (2026-10-08)

Twelve raw frames of one scene (game mode off, `adb screencap`) replayed through
`GameTextSourceReplayTest`, then 26 live advances. The replay is what found
these; each fix was checked against it before going back to the game.

- **Names cut in the wrong place, or not at all.** The ink colour took in
  every pixel far from the column's backdrop, lighter *or* darker, so the
  glyphs' dark outline and the art through it came in too: a thin white リ
  read grey, イオリ was cut after イオ, and チナツ not at all. Ink is now only
  the line's own side of the backdrop (lighter, if most of the contrast is
  lighter). Replayed, all twelve name rows split right and no line of dialogue
  was cut.
- **The pieces read their neighbour's edge** — 「アコ,」, 「|風紀委員会」,
  「1風紀委員会」 — because the margin ML Kit needs was taken from the frame.
  It is now the piece's own backdrop colour.
- **A name a cut too long**: レイジョ is 61% of its row; the cut may now fall in
  the first 75%.
- **The speaker joined to the dialogue**, 200 px tall, on some frames of
  two lines in eight. The dialogue's box came back 56 px tall on one frame and 72 on the
  next (ruby, or slack), and at 72 it matched the name's height. Three rules
  now: a wrap is at most 0.75 of a line's height below (measured 34–38 px under
  55–57; the speaker row sits 52–72 above); heights are compared on the ink,
  not the box; and a row of two pieces side by side is a label, never a line
  of a paragraph.
- **The end of a sentence dropped**: a wrap of a word or two (「ね!?」) was too
  short to keep alone; it is kept under a kept line. A third line wraps under
  the second, not under the two joined. A first line read without its leading
  「……」 starts up to two line heights further in and still joins.
- **The affiliation's translation stayed put** after a longer name moved the
  affiliation along (589 → 674 px) and covered the new name. A published line
  whose box shifts whole by more than half its height is drawn again; a box
  that stretches on one side, as the recogniser's does, is not.
- **A two-line translation withdrawn and drawn again** when one frame read only
  its first line: a reading that is clearly shorter and reads as the
  beginning is a miss, not a new line.

Same-text affiliations (玄武商会 is the same in Chinese) show no box; that is
the coordinator dropping an identical translation, not a miss.

**MIUI freezes the service unless its battery setting is 无限制.** After an
update, with the game launched straight from the launcher, game mode read
nothing. `dumpsys greezer` shows MIUI's own freezer (not Android's —
`isFrozen=false` there) freezing Babel's process when a game starts
(`LM FZ … 10411`, `cgroup.freeze` = 1); the window list the service holds stays
on the launcher until the process is thawed, which opening Babel does. With
Babel's 省电策略 set to 无限制, the same sequence — update, launcher, game —
read the game within a second of it coming to the front, and Babel was no
longer in the freeze lists. So on MIUI/HyperOS that setting is a requirement
of game mode, not a nicety; telling the user so is not built yet.

### Erase and redraw (2026-10-09)

Blue Archive, three story episodes and the story menus, about 80 advances.

- A line on a panel (`backdropError` up to 36, three times the translation
  threshold: speaker rows on the dialogue box's translucent edge measured
  14–31) is painted back from the colours at the two ends of each row and the
  translation set in its place: the original's ink (its strongest 30% of
  pixels — the mean came out grey), its height, bold when its strokes are
  over 0.11 of the height (measured 0.14–0.18), from its left edge.
- What had to be measured to get there: the type's height from rows against
  the panel read *outside* the box (the column's own middle value hid thick
  strokes: a line read 37 px for 55); room for a CJK line, 1.45 of the text
  size, or the translation shrank to 60%; the patch grown out to all the ink,
  across small gaps (a dropped 「！」, a 「――」 300 px long, ruby over the line)
  but never past halfway to the next piece on the row (a short name's patch
  ate 「玄」 of the affiliation); edge samples that landed on stray ink repaired
  from the neighbouring rows (`BackdropEdges`: a white line ran through one
  translation).
- No outline was found on Blue Archive's type (its edge is under 2 px); the
  outline is drawn where the ink against the panel falls under 4.5:1.
- **Flicker of the speaker row** was the affiliation read two ways one glyph
  apart, each withdrawing the other. A reading one edit from the published one
  (four characters or more) is the same line. Withdrawals are now logged with
  their reason; over the last ten advances every one was a real change of
  speaker or line, or a scene change.
- **Long press** switches the whole screen to the original and back; the next
  line restores the translation.
- **AUTO and MENU** are not translated in a Japanese game
  (`GameLayout.controls`), and every label is drawn in a window that lets
  touches through.

### Whole-app pass before syncing (2026-10-11)

- **V1** (Wikipedia, text translation): translated in place as before.
- **V2** (manga mode on a Chinese comic app): its Chinese list was rewritten by
  the chat model — 「[16P]一人之下」 as 「「16P」之下」, 「历史」 as 「万岁」. Text already
  in the reader's language is no longer sent (`SameLanguageGuard`): a source
  said to be the target, or Han without kana for a Chinese reader when the
  source is unknown. A Japanese game marks its kanji-only lines Japanese once
  kana has been seen, so 「風紀委員会」 is still translated.
- **A third game, Shattered Pixel Dungeon** (portrait, pixel font, switched to
  English): found three things the two landscape games could not.
  - Sizes were judged against the frame's height, 3200 upright: its 50 px
    body text was scenery. They are judged against the short side.
  - Its title screen's animated art made every frame "busy" and its menu was
    never translated. Motion alone is not play; motion with counters is.
  - A pixel font fills more than half of some rows, and the patch took those
    rows' ink for panel: lines through every button. The panel per row comes
    from above and below the text, and over art from the row without its ink.
- **Draw-over-apps permission**: after an update MIUI withheld it for minutes
  and every game translation was refused. A game's windows are the
  accessibility service's own (`TYPE_ACCESSIBILITY_OVERLAY`), which need no
  permission.
- Latin words inside a game's other-script text (the player's name) travel as
  placeholders (`KeptWordsTranslator`): asked in words to keep them, the model
  still rendered 「yizhiteamo」 as 「一支队伍」.

### History screen (2026-10-11)

Fate/Grand Order's LOG is drawn translucent over the game's dialogue box, and
the recogniser read now the history and now the dimmed dialogue behind it:
over 10 s, 25 translations drawn and 25 withdrawn. Measured, the line behind
has a fraction of the ink of the one over it (37–57 per thousand against
264): of lines read over each other only the one with at least a third of the
other's ink is kept (`frontLayer`). Same 10 s afterwards: none. A place two
readings take turns at is also remembered, and the second reading no longer
withdraws the first (`StableLines`). A chosen answer in the history, set in
red, was left out as too large: its box was 106 px around 71 px type, and size
is now judged by the type. Scrolling the history by dragging on a
translation did nothing; the drag is handed on when the finger lifts.

Second pass on the history screen: ink alone did not hold. Its last entry,
over the game's own dialogue box, was read six ways — the line behind taken in
whole, in part, or merged with the speaker's tab — and still withdrew and drew
itself 19 times in 9 s. A line whose pixels have not changed (no cell of a
24×4 brightness grid of its box moved by more than 12) now keeps its last
reading, unless a fresh reading reaches past its box, which is how a
typewriter's next characters show: 9 s on the same screen, no changes, and a
following ten lines of story read as before. Readings mostly the same
characters (0.6 and over) no longer withdraw each other either. Lines long
enough to be whole (12 characters) are published at once when read again
exactly, as labels were, so a scrolled history comes back faster.

### Story only (2026-10-11)

Blue Archive's mission menu, translated: 「合同火力演習」 came out as 「大决战」
and 「演习」 over the remains of the tile, 「臨時性試験」 as three different
guesses in a minute, the tiles' badges flickering. Decided: game mode
translates the story, not the interface (`docs/features/v3-game-translation.md`).
Only dialogue (`GameLayout.dialogue`) is shown, on every screen; the busy-scene
switch that did this for battles alone is gone. What counts as dialogue was
tightened for it: punctuation needs four letters (a badge's 「開催中!」 is not
a sentence), a lone 「 or 」 does not count, and two tiles read as one spaced
line are labels. Short replies such as 「うん」 are kept by place: the box and
name tab a conversation was in during the last minute. The same menu now shows
nothing translated; the story menu's synopses are, and ten lines of story read
as before.

### Stepping aside on a tap, and names sent as names (2026-10-11)

- A tap on the dialogue now hides its translation at once; the line that comes
  types out in the original until its own translation is ready. Before, the
  last line's translation stood 0.7–1.5 s over the next line. A tap that did
  not move the dialogue on gets the translation back after 1.5 s.
- Speaker names went with the story as context, and one came back as two
  lines (「玄龍門」 → 「玄武商会
玄龙门」, the last speaker's affiliation
  first). Names go without context, as names (`TranslationRequest.Hints`);
  alone, 「ヒナ」 had become 「雏」, "chick", and is 「日奈」 again. A one-line
  source keeps a one-line answer. Cache schema 3, so old answers are not kept.
- A name read one character off one already shown is that name

### Sizes from the type's width; speakers in a chat (2026-10-12)

- **Size.** Ink height overstated Blue Archive's chat type by 13% (41 px a
  character across, set at 46.6), so short bubbles' translations no longer fit
  and were shrunk. The size of each kind of type is now the median of its
  lines' width per character (full-width 1, others 0.55, one-line lines
  only), clamped to 0.75–1.15 of the height-based size. One-line translations
  are sized by width alone — fitted to the patch's height as well, a tight
  bubble's 「老师」 came out at two thirds — and an original of one line stays
  one line while the text fits at all (「嗯——」 was broken after its first
  character).
- **Weight.** The median of each kind's first twelve lines, then fixed; every
  line of a batch takes it once all are measured. A running mean drifted over
  a step in weight mid-chat.
- **Speakers.** In a chat's column a label is a message unless the same words
  stand there over another run (or were a sender lately): 「待ってください」 and

- **Joins.** Two labels stacked are two things (「んー」 / 「先生」, a bubble each,

- **Not translated.** A real 「？」 a box ended inside of measured 0.7–10% type
